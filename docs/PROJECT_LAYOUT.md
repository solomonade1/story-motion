# Local project storage layout — v1.0.0-phase0 (baseline for G0)

**Status:** the layout actually used by the Phase 0 headless worker. Phase 1 will add per-project SQLite metadata and versioned project
JSON with atomic autosave (FR-PROJ-002/004); this layout will then get a migration, not a silent change.

```
projects/<name>/
  script.txt                  one narration paragraph per line (input)
  audio/                      narration.wav (generated or supplied), optional bed tracks (music/ambience)
  clips/                      videos made elsewhere (e.g. Blender, other tools)      -> asset type rendered_video
  images/                     full-frame pictures                                    -> asset type environment
  layers/                     transparent PNG cut-outs                               -> asset type prop/character
  narration.timing.json       per-line speech start/end (ms), written by scripts/make_narration.py
  assets.scan.json            output of `scan` (hashes, probe data, problems, warnings)   [generated]
  plan.json                   human-edited shot plan (lines/cues, clip/trim/speed, transitions, bed tracks)
  manifest.json               validated scene manifest (schema 1.1.0)                 [generated by `build`]
out/                          rendered MP4s, reports, previews (git-ignored; safe to delete)
tools/                        pinned FFmpeg build, Piper voices (git-ignored)
```
Rules: source assets are **never modified**; outputs are **never overwritten** without an explicit flag; every asset is identified by
SHA-256; asset paths are relative POSIX paths and cannot leave the project folder; provenance (`source`, `license`, `licenseVerified`)
is recorded per asset and defaults to *unverified*.
Contract version: manifest `schemaVersion` **1.1.0** (1.0.x still readable). Renderer version: `PROCESSOR_VERSION` in
`workers/media/storymotion_media/__init__.py`.

# Studio workspace layout — v1.1.0-phase1 (Phase 1; decisions in ADR-0008)
```
<workspace>/                     default ~/StoryMotion Studio  (or $STORYMOTION_WORKSPACE, or --workspace)
  index.sqlite                   project list cache (rebuilt from the folders if lost)
  .worker.lock                   one worker per workspace (OS lock; released automatically if the process dies)
  .trash/p-<id>-<UTC stamp>/     deleted projects, recoverable until purged
  projects/p-<12 hex>/
    project.json                 project document, schema 1.0.0  (atomic writes; keeps project.json.bak,
                                 .corrupt-<stamp> and .premigration-<stamp> files as evidence)
    project.sqlite               assets (hash, category, probe data, status, preview paths) and jobs
    assets/  thumbs/  proxies/   copied media; 320 px thumbnails; 360p/1280px preview proxies (discardable)
```
This is a *different* thing from the Phase 0 episode folders above (`projects/<name>/plan.json`...), which stay supported for the headless
render commands. Bringing a Phase 0 folder into a Studio project is not built yet.
